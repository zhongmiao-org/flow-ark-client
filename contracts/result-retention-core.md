# 完整结果保留核心

0.51.0 固定规范，与 [政策](result-retention.md) 及 [目录](result-ledger.md) 同时适用。

## 身份、范围与数值

`RetentionSet`恰有`version:1,runId,roots,cells`。同一集合只属一个Run；根与内容不能跨Run、实例或工作区共享。存储身份必须至少包含数据拥有者、准确Run与单元摘要，不能只按摘要进行全局查找。`runId`为1–100个Unicode标量且不含代理字符的非空文字；格式不证明该Run真实存在或可访问。

根恰有`resultId,root,sha256,bytes`：`resultId`为原逻辑结果身份的64位小写SHA256，仍须宿主按Run/固定节点实例/type生成并复验；`root`指向内容单元；`sha256`是完整规范JSON的SHA256；`bytes`是完整规范JSON的UTF-8字节数。JSON原对象成员顺序不构成业务含义；数组顺序、所有键和值必须保持。不同根即使内容相同也分别计数，不能合并节点或事实身份。现有配置/状态结果可达2MiB，资料解析另有8MiB输入上限；本核心不能擅自把所有类型限制为1MiB。各类型原有限额仍须独立校验，本核心上限不扩大其原授权或类型预算。

本版本固定：最多1000根、16384个唯一单元；完整单值最多8388608字节、JSON深度64、JSON值访问262144次；单元编码最多16384字节、组合分组32（成员组最多32对键/值，即64个引用）、图深度256。累计单元展开工作最多128MiB及262144次引用访问，超限整次拒绝。限制不是截断，任何不能完整复原的值不得采用。

`roots`按resultId、`cells`按id以ASCII升序排列且各自唯一。保留字节为整个规范RetentionSet的UTF-8字节数，最多8388608；根、单元身份、组成引用、数组标点和集合头都计入，不只计算叶正文。完整内容累计为各根bytes之和，是另一统计值；不是数据库文件大小或磁盘空闲保证。此8MiB是新保留政策，不能替换旧Run的逐结果完整值累计语义。

## 规范JSON与摘要

仅接受有限数、布尔、null、字符串、稠密数组及无访问器/隐藏成员/符号成员的普通JSON对象。负零按JSON的0处理；不接受NaN、Infinity、undefined、函数、稀疏数组、自定义原型或toJSON转换。UTF-16孤立代理在字符串内容中用JSON转义保留，不能替换为U+FFFD后声称无损。

规范字节与现客户端排序后JSON序列化口径一致：对象的数组索引键（规范十进制0至4294967294）先按数值升序，其余键按UTF-16代码单元字典序；值递归采用同样规则，字符串和有限数采用ECMAScript JSON序列化表示。不得把另一种全键字典序序列化当作该摘要；例如数值键2排在10之前。各语言实现必须提供等价序列化，不能使用本地默认键顺序、浮点文本或Unicode排序。

单元记录恰有`id,cell`。单元id为SHA256(UTF-8(`flowark-result-cell-v1` + U+0000 + 规范JSON(cell)))，与完整值摘要分域。相同id只有规范单元内容也完全相同时才能复用；不凭哈希相同跳过拥有者与内容核验。

## 确定性编码

1. 某完整子值的规范JSON不超过4096字节时，生成`json`单元，text为该完整规范JSON。单元自身的再次JSON编码/身份开销仍计入保留预算。
2. 更长的字符串先取得其完整规范JSON的UTF-8字节（含引号和转义），从0开始按4096字节切片，允许切在UTF-8码点中间。每片保存在`bytes`单元的标准带填充base64中；只有拼接完整后才能以严格UTF-8解码。不能分别解码各片并替换无效字符。
3. 多片按顺序每32个引用生成`concat`单元，逐层每32个引用组合至一个顶点；最后生成`text`单元的body引用。只有字符串走此路径。空串已落在json叶中。
4. 更大的数组先依次编码各元素；每32个元素引用生成一个`list`单元。多个list按每32个有序引用生成`array`单元，逐层组合至一个顶点。list代表实际元素序列，array只连接list/array所代表的序列，不把分组变成业务嵌套数组。
5. 更大的对象按规范键顺序编码键字符串及值；每32对键/值引用生成一个`members`单元。多个members按每32个有序引用生成`object`单元，逐层组合至一个顶点。object只连接members/object所代表的成员序列，不引入额外业务字段。键必须重建为字符串且不重复；用安全的成员构造方式保留`__proto__`等字面键。
6. 每个阶段相同单元去重，按id排序输出；根保持完整摘要/字节。数组/对象不超过4096字节时必须使用json叶，不能任意选另一种分组。编码结果须可确定性重编码，禁止靠不同分块绕过计量或让恶意非规范图被接受。

单元格式由[result-retention.schema.json](result-retention.schema.json)固定，关系/编码由`result-retention.mjs`固定；JSON Schema不能单独证明字节、摘要、排序、拥有者、无循环或完整性。参考只进行纯内存关系，不访问数据库、Key、文件、浏览器、模型或网络，不证明生产持久化、权限、磁盘故障或保留期限。

## 完整核验、合并与删除

读取先校验有界格式、排序/唯一、每单元摘要、全部引用存在和类型角色、无循环/超深、全部单元可从根到达，再按准确根完整重建。重建必须核对根sha256/bytes，并以同一确定性编码重新核对其根及单元身份，任何缺失、跨拥有者、错摘要或替代编码整次拒绝。禁止把部分文本、部分对象或尚未核验的投影返回给模型/后续动作。

合并只允许同一Run；同resultId须根记录完全相同，否则拒绝身份冲突。同单元id须内容完全相同。新的根/单元/索引必须和预算复验同事务提交；不留下孤立块或半条结果。预留应按当前保存集合与全部未消费候选的唯一联合计量，不能假设各自可放入就同时可放入。参考合并结果不构成任何执行许可。

不能按“没有当前UI引用”删除单元。保留根、来源证明、确认Skill、前次结果绑定、固定快照、操作回执或其他事实引用必须先核对；当前不定义自动GC、根删除API或清库。未知/孤立引用保留并停止相关维护，不提供force修复。旧Run不在启动/查看时补块、转换政策或重写摘要。
