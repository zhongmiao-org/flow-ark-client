# 固定 Run 完整结果保留政策

2026-10-21，0.51.0 的生产规范。核心编码、根/组成单元及完整重建见 [result-retention-core.md](result-retention-core.md)，目录、真实副本家族及事务要求见 [result-ledger.md](result-ledger.md)。本文件将两者与 P1、私有宿主快照和只读容量响应关联；三份规范同时适用。纯参考不证明存储来源、权限或执行许可。

## 新旧政策及生效

`RunSnapshot.resultRetention` 可选且只能为 `{version:1,policy:"run-owned-results-v1"}`。宿主在准备新 Run 时选择政策，放入私有 `PreparedScripts.resultRetention` 的等价固定字段，并将其纳入 `executionVersion` 摘要；不能只改公开类型而漏掉实际执行版本。目录 owner 同时固定真实 runId、flowId、执行 versionId 和完整不可变私有快照的规范 JSON SHA256。snapshotSha256 是实际快照的摘要，不把目录自身放入快照产生递归。

新 Run、快照和空目录在同一创建事务内登记；没有标志的旧快照才采用 `legacy-full-values-v1`。有新标志但缺目录、来源不符或未知政策须明确不可核验，不能回退旧政策。新政策仅在全部实际结果生产者、恢复写入和读取适配后启用；没有适配的流程在创建 Run 前阻止，不按节点类型猜测安全。不可变历史重跑创建新 Run 时重新准备，新政策不回填旧 Run 或修改旧版本。

政策属于宿主本地输出存储，没有新增模板能力声明、业务节点或 SDK 方法；Flow 和公开 ZIP 不携带目录、Run 政策、个人原值或许可。包 2.0/SDK 1.0 维持，旧 `state.set` 的 boolean/非 CAS 语义维持。旧快照及既有机器资料封存不改。

## 生产存储及完整读取

目录为固定 Run 自有单一受保护记录，根和内容均不跨 Run/实例/工作区引用。根内容与逻辑元数据、仍存在的完整回执/投影等副本，以及目录更新必须和原生产行的状态转移同事务。新值须完整校验原类型 Schema/原有限额，再编码、完整重建并核对原摘要后才能登记。幂等只能接受相同来源和相同完整内容。状态写入须在 prepared 前核对全部阶段峰值及未消费预留，不能提交后再发现可预测额度不足。

容量读取先取得一致宿主视图，核对准确 Run/快照拥有者、目录 Schema/全部图引用和单元摘要、所有实际副本清单及完整摘要/字节。不为统计重建每个重复逻辑值；完整根的来源保证来自原事务登记与只读保护，读取单项时仍须完整重建并复验。缓存只在目录 revision 和全部受计量 Store 写入代次均不变时复用。实际源变化/缺失/漏登记、无法取得一致视图或任一读取失败均返回不可核验。不能由 Renderer 提供计量、拥有者或任意存储 key。

读取单项不返回部分重建值。原来源权限、当前秘密保护和每类结果的完整 Schema 复验保持；新目录不是任意历史值接口。RawCopy 的 id 由宿主按固定家族、实际 kind/key/字段投影生成摘要，不能由模板指定。生命周期、独立归档/资料/当前状态和引用保护见目录规范；不新增删除、GC、隐式清库或旧数据迁移。SQLite/受保护 KV 的物理布局由客户端实现，不将裸数据库 key 作为公共协议。

## 只读容量响应

`RunResultCapacity` 作为现有 Run 详情/输出读取的附加元数据，服务端宿主生成；不新增独立模板调用或任意查询接口。一次响应恰属一个准确 runId。各对象拒绝额外字段，调用方先做固定 Schema 校验，再 `verifyCapacity` 关系核对。最大结果数 1000、保留字节 8388608，单结果及家族原限额独立适用。

- 新政策 available：revision、逻辑 count/logicalBytes、catalogBytes、copyBytes/copyCount 和 retainedBytes；后者严格等于目录规范 JSON 字节加真实副本字节。logicalBytes 为根完整值累计，可以超过 8MiB；不把共享内容按类型重复分摊为实际占用。
- 旧政策 available：只给 count/logicalBytes/retainedBytes；后两者相等，沿用原完整结果累计口径，不对旧 Run 宣称已经补计其他副本。不能用于新政策准入。
- unavailable：仅 version/runId/policy/status/reason，无计数、部分值或错误正文。reason 为 missing（缺必要记录）、owner-mismatch（来源不符）、integrity（结构/摘要/副本关系不符）、limit（已存格式或工作超限）、storage（无法读取一致源）。客户端使用可读提示，不显示内部 key 或哈希为正常交互。

零逻辑结果仍可存在原值副本和非零目录；available 的 count/logicalBytes 为 0 不代表占用 0。不可核验不能伪装成空结果。容量 UI 位于输出区独立于逻辑结果列表是否为空，展开只读元数据；原文继续原有独立完整阅读入口。显示空结果/仅副本状态前先补既有 Figma 明暗设计，不据本契约声称 UI 已实现。

## 独立的外发保护段

本存储政策不承诺网页/外部提交之后整段结果的可用空间。现有单次状态预留也不覆盖外部动作后的全部来源、去重状态、回执和必要完整结果。该保护段仍需独立契约及宿主实施，容量数字不是外发许可。公共连续 BOSS 必须同时具备保护段、连续会话的真实进度/无进度停止及独立复导证据；单独发布本版本不能标记这些目标完成。

## 固定版本及消费者顺序

此目录机器资料由 SHA256SUMS 封存，治理先合并、发布准确 `contracts-v0.51.0` tag 后客户端才从远端该 tag 独立采用。客户端须分别取得全部家族、原子保存/完整读取、旧历史及失败路径、普通 UI 和独立标准 ZIP 复导证据，再声明政策可用。治理格式/关系编译不代表消费者、安装或真实招聘通过；当前完整业务终点仍是 BOSS 网站实际每日 150 次打招呼上限弹框，回复后附件和有序聊天另行验收。
